🎓 شهادات Coursera — مراجعة بالساعات الرسمية (مطلوب vs تكميلي) + إضافة أساس بطلبك

راجعنا مناهج الشهادات فعليًا على موقع Coursera: لست مطالبًا بكل كورس في كل شهادة. الأساسيتان في مسارك هما Google IT Automation و IBM Applied DevOps، أما Google Cybersecurity فتخصص اختياري إضافي لمرحلة DevSecOps. الأساسي موزع على الوحدات، والتكميلي اختياري عند الحاجة — لتجنب التكرار وضياع الأسابيع. تنبيه مهم: دراسة كورسات منتقاة تعني أنك لن تحصل على الشهادة الورقية الكاملة (تتطلب إتمام كل الكورسات والمشاريع)؛ الأولوية هنا للمهارة المطلوبة لهدفك، والشهادة الكاملة قرار اختياري لاحق.

تكميلي: Troubleshooting & Debugging (19س) عند الحاجة، وكورس التسريع الوظيفي بالذكاء الاصطناعي (6س) اختياري.

💻 الجهاز اليومي: Fedora Workstation (i5-6200U / 8GB / SSD+HDD)

Workstation

يُستخدم كمحطة عمل رئيسية (Control Node) لكتابة الأكواد، إدارة مستودعات Git، تشغيل AWS CLI و Terraform، وبناء حاويات Docker المحلية السريعة على قرص الـ SSD.

  • توزيع التخزين (SSD + HDD): ثبّت نظام الجذر / وملفات المشاريع النشطة على الـ SSD لسرعة الإقلاع، واجعل صور الحاويات الكبيرة والنسخ الاحتياطية على الـ HDD.
  • إدارة الذاكرة (8GB RAM): استخدم VS Code أو Neovim مع إيقاف الإضافات الثقيلة عند تشغيل عناقيد Kubernetes محلية (يفضل تشغيل K3s على جهاز المختبر وتوجيه kubectl من Fedora).
  • الأدوات المثبتة محلياً: aws-cli, terraform, ansible, kubectl, helm, git, podman/docker, trivy.

🖥️ خادم المختبر: Rocky Linux Minimal + Kickstart (i3-2200 / 4GB / HDD)

Home Lab Server

يعمل كخادم لينكس حقيقي بدون واجهة رسومية (Headless Server) لاستهلاك أقل من 350MB RAM عند الإقلاع، مما يوفر قرابة 3.5GB RAM لتشغيل خدمات البنية التحتية.

  • الأتمتة بـ Kickstart: في الوحدة 3 والوحدة 16، ستبني ملف anaconda-ks.cfg لإعادة تهيئة الخادم تلقائياً بضغطة زر مع تقسيم LVM وتفعيل جدار الحماية و SSH Keys.
  • تحسين أداء قرص HDD والذاكرة 4GB: تفعيل zram لضغط الذاكرة العشوائية، وتجنب تشغيل Jenkins و GitLab معاً في نفس اللحظة (تشغيل الخدمة المطلوبة للوحدة الحالية فقط عبر Docker Compose أو K3s).
  • ربط الشبكة: ربطه مع جهاز Fedora عبر SSH ومفاتيح ED25519 وعبر شبكة Cloudflare Zero Trust / Tailscale المجانية للوصول الآمن من أي مكان.

🗓️ تقسيم كل شهر إلى 4 أسابيع وجلسات دراسة (2-3 ساعات يوميًا)

تحليل فيديو خريطة طريق مهندس الكلاود (DolfinED) وتبرير تحسينات هيكلة المسار

تمت دراسة وتحليل الفيديو المرجعي Cloud Engineer Roadmap | خريطة طريق مهندس الكلاود (2026) للمهندس عيسى (قناة DolfinED)، ومقارنة تسلسله المنطقي مع خارطة طريق مصطفى لتطبيق التعديلات الهيكلية الأكثر منطقية وظيفياً وعلمياً.

1. نهاية عصر الشهادة المنفردة ("البرشامة السحرية")

يؤكد الفيديو بوضوح أن الحصول على شهادة Cloud Practitioner أو حتى SAA-C03 وحدها دون إتقان Linux و Terraform و Docker و Git وبناء مشاريع عملية لم يعد يوظف أحداً في سوق العمل الحديث منذ 2020 وحتى 2026.

2. التسلسل التراكمي القائم على التبعيات (Scaffolding)

يرتب الفيديو المهارات بحيث تخدم كل أداة الأداة التي تليها مباشرة: تعلم مبادئ الشبكات والسحابة أولاً، ثم حساب AWS لتطبيق Linux عليه، ثم Bash و Git لحفظ السكريبتات، ثم Python، ثم YAML قبل Docker و Kubernetes، ثم Terraform و SAA-C03 و CI/CD و Ansible.

3. الإطار الزمني الواقعي (8 إلى 9 أشهر) والمشاريع

يشدد الفيديو على أن التحول الحقيقي من مبتدئ تماماً إلى مهندس جاهز للمقابلات التقنية يتطلب 8 إلى 9 أشهر من العمل المستمر وبناء محفظة مشاريع على GitHub، مع استخدام أدوات الذكاء الاصطناعي للمراجعة والتسريع فقط بعد الفهم العميق.

🔄 مقارنة التسلسل وإثبات التغييرات الهيكلية المبررة في خارطة طريق مصطفى

التعديل الهيكلي الوضع في المسارات التقليدية القديمة التسلسل المعتمد بناءً على تحليل الفيديو التبرير الهندسي والتربوي (لماذا هذا الترتيب أفضل لمصطفى؟)
1. دمج أساسيات الشبكات و TCP/IP مع مفاهيم الكلاود في الوحدة 1 (بدل كورسات CCNA/A+ المنفصلة) قضاء 3-4 أشهر في دراسة A+ و Network+ و CCNA كاملة قبل لمس السحابة أو لينكس. الوحدة 1: أساسيات تكنولوجيا المعلومات والشبكات (TCP/IP, DNS, Routing) ومفاهيم الحوسبة السحابية معاً. كما أوضح الفيديو (الدقيقة 08:45)، دراسة CCNA كاملة للمبتدئ الراغب في الكلاود تستهلك أشهراً في بروتوكولات أجهزة سيسكو التقليدية، بينما يحتاج مهندس الكلاود إلى فهم عملي مركز لـ IP، Subnetting، DNS، HTTP/HTTPS، و Virtualization للدخول فوراً في بيئة AWS ولينكس.
2. تقديم مدخل خدمات AWS الأساسية (الوحدة 2) قبل التعمق في Linux (الوحدة 3) تأجيل فتح حساب AWS إلى منتصف المسار بعد إنهاء Linux و Bash و Python بالكامل. الوحدة 2: مدخل خدمات AWS الأساسية (IAM, EC2, VPC) ثم الوحدة 3 و 4: إدارة Linux على كل من خادم Rocky المحلي ومثيلات AWS EC2. يتفق هذا مع ترتيب الفيديو (الدقيقة 09:12) ومع هدف مصطفى في التركيز المستمر على AWS منذ الشهر الأول؛ حيث يتيح لمصطفى تطبيق أوامر Linux وإعدادات الشبكات بالتوازي على خادم المختبر (i3-2200 Rocky Linux) وعلى مثيلات EC2 المجانية في سحابة AWS.
3. وضع Git و GitHub (الوحدة 6) مباشرة بعد Bash (الوحدة 5) وقبل Python و Docker و Terraform وضع Git كأداة ثانوية قريباً من نهاية المسار عند دراسة أنابيب CI/CD. الوحدة 5: Bash Scripting ثم الوحدة 6: إتقان Git و GitHub، تليها الوحدة 7: أتمتة AWS بلغة Python. أكد الفيديو (الدقيقة 10:02) أن المهندس سيكتب عشرات السكريبتات وقوالب Terraform وملفات Kubernetes YAML، لذا يجب أن يتقن Git و GitHub مبكراً جداً لحفظ إصدارات الكود وبناء معرض مشاريع (GitHub Portfolio) منذ الشهر الثالث.
4. تخصيص وحدة مستقلة للغة YAML وبيانات التهيئة مع Docker (الوحدة 9) قبل Kubernetes (الوحدة 10) الدخول في Docker Compose و Kubernetes و Ansible مباشرة دون تأسيس هيكلي للغة YAML مما يسبب أخطاء المسافات البادئة (Indentation Errors). الوحدة 9: إتقان لغة YAML وتقنية الحاويات Docker & Docker Compose، تليها الوحدة 10: تنسيق الحاويات Kubernetes & AWS EKS. أشار الفيديو (الدقيقة 11:01) إلى أن تعلم YAML في البداية يزيل أكبر عقبة يواجهها المبتدئون عند كتابة ملفات docker-compose.yml و k8s manifests ومهام GitHub Actions وخطط Ansible Playbooks.
5. وضع Terraform (الوحدة 11) ومعمارية AWS SAA-C03 المتقدمة (الوحدة 12) بعد فهم الحاويات وقبل CI/CD دراسة Terraform قبل معرفة ما هي الحاويات أو قواعد البيانات أو موازنات الأحمال التي سنقوم بأتمتة بنائها. الوحدة 8 (خدمات AWS للشبكات وقواعد البيانات) + الوحدات 9-10 (Docker & K8s/EKS) ← ثم الوحدة 11 (Terraform IaC) والوحدة 12 (معمارية AWS SAA-C03). كما ورد في الفيديو (الدقيقة 11:18)، عندما يتعلم الطالب Terraform بعد أن يكون قد جرّب بناء VPC و EC2 و Docker و EKS، يصبح قادراً على تحويل كل ما تعلمه إلى كود برمجي (IaC) وتصميم معماريات SAA-C03 احترافية.
6. تجميع أنابيب CI/CD (GitHub Actions & Jenkins في الوحدة 13 + GitLab CI في الوحدة 14) متبوعة بـ Ansible (الوحدة 16) تشتيت أدوات الأتمتة والنشر المستمر في أماكن متباعدة. الوحدات 13 و 14 (CI/CD شاملة) + الوحدة 15 (المراقبة Prometheus & Grafana) + الوحدة 16 (Ansible & RHCE على AWS ومختبر Rocky Linux). ينسجم تماماً مع خطوات الفيديو (الدقيقة 11:36 - 11:50) حيث يقوم المهندس بربط البنية التحتية (Terraform) مع نشر التطبيقات الآلي (CI/CD) وتكوين الخوادم المركزية (Ansible).
7. حصر Azure و GCP في الشهر التاسع فقط (الوحدة 18) وتأجيل DevSecOps للمرحلة الثانية (الوحدات 19-27) خلط AWS و Azure و GCP معاً في البداية مما يربك المبتدئ، أو إدخال أدوات الفحص الأمني قبل فهم بناء الأنابيب أصلاً. الشهر 1-8 تركيز خالص على AWS؛ الشهر 9 (الوحدة 18): مقارنة متعددي السحابة مع Azure (AZ-900) و GCP؛ ثم المرحلة 2 (9 وحدات): DevSecOps. يطبق نصيحة الفيديو (الدقيقة 02:10 و 11:53): إتقان سحابة واحدة (AWS صاحبة الحصة السوقية الأكبر) يجعل تعلم Azure أو GCP في النهاية مسألة مطابقة مصطلحات (Mapping) لا تستغرق سوى أسابيع قليلة، ويمنح أرضية صلبة للتخصص في DevSecOps لاحقاً.

📲 تثبيت التطبيق للعمل دون اتصال (Fedora Desktop & Mobile)

💻 على نظام Fedora Workstation (Chrome / Brave / Edge / Firefox): اضغط على أيقونة تثبيت التطبيق (Install App ⊕) الموجودة في شريط العنوان أعلى المتصفح، أو من القائمة اختر "تثبيت أكاديمية مصطفى السحابية" ليظهر كبرنامج سطح مكتب مستقل في قائمة تطبيقات GNOME.
📱 على الهاتف المحمول (Android & iOS): في متصفح Chrome على أندرويد اختر "إضافة إلى الشاشة الرئيسية / تثبيت التطبيق"، وفي متصفح Safari على آيفون اضغط زر المشاركة (Share) ثم اختر "إضافة إلى الشاشة الرئيسية (Add to Home Screen)".
⚡ ميزة العمل الكامل دون إنترنت (True Zero-CDN Offline): تم دمج جميع التنسيقات والخطوط والبيانات داخل التطبيق وتخزينها في Service Worker، بحيث يعمل التطبيق بسرعة فائقة حتى عند انقطاع الإنترنت تماماً.
